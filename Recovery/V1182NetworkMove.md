# 1.18.2 인터넷 이전 후 서버 경로 점검 (2026-09-27 KST)

- 운영 서버는 새 네트워크에서도 요청을 받는 상태다. 기존 공개 터널 1개가 live이고 서버 PC의 로컬 목적지까지 연결된다. 앱에 저장된 기본 공개 주소는 변경할 필요가 없어서 공유기 포트포워딩·서버 재시작·DB 이전을 하지 않았다.
- 서버 PC 내부, 앱에 설정된 공개 경로 각각의 진단 POST가 HTTP 204를 반환했다. 두 경로에서 앱 프로토콜 버전4 HELLO/HELLO_OK와 PING/PONG 실제 소켓 검사도 통과했다.
- 서버에 반영된 두 계정·결과 모듈은 소스와 일치한다. 기존 계정 21개, SQLite integrity ok. 사용자 계정과 운영 DB를 변경하지 않았다.
- 앱에 이전 인터넷의 주소를 수동으로 저장했다면 로그인 화면의 서버 설정에서 현재 앱 기본 공개 호스트/포트를 다시 저장해야 한다. 기본 공개 주소는 소스 `PhoneLOLServerSettings.cs`를 참조한다. 내부망에서 직접 접속할 때 필요한 새 LAN 주소는 운영 PC의 비공개 기록에 보관했다.
- 이전 1.18.1의 URF·전적·카타리나·알리스타·채팅·서버 연결 실패 시 선택형 로컬 1인 모드를 포함한다. 다른 통신사의 실제 휴대폰 연결과 한 판 완료는 아직 실기기 미검증이다.
- 공인 IP 조회는 자동 승인 검토가 외부 IP 조회 서비스에 새 IP를 공개한다는 이유로 거절했다. 기존 공개 터널을 통한 실제 통신으로 필요한 접속 경로를 검증했다.
- 자동 검사 소스: `Automation/Server/check_v1182_public_path.py`. 공유 대상에 내부 주소, 터널 식별자 또는 사용자 계정 자료를 넣지 않는다.
